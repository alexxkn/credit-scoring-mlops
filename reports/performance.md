# Производительность модели и сервиса

Замеры на ноутбуке: Intel Core Ultra 7 255H, NVIDIA RTX 3080 Ti (eGPU, USB4), PyTorch 2.11, ONNX Runtime 1.32. Полные таблицы: reports/benchmark.md, reports/optimization.json, reports/load_test/.

## Модель

Нейросеть: MLP 40 → 128 → 64 → 1, предобработка (агрегаты платежей, масштабирование, one-hot) внутри графа, поэтому ONNX-модель принимает 23 исходных признака клиента.

| | ROC-AUC test | F1 | Brier |
|---|---|---|---|
| MLP | 0.7745 | 0.5250 | 0.1362 |
| случайный лес (курс 17) | 0.7795 | 0.5414 | 0.1783 |

MLP уступает лесу 0.005 по ROC-AUC, но выдаёт откалиброванные вероятности: Brier 0.136 против 0.178 у леса и 0.172 у константного прогноза.

## Конвертация в ONNX

python -m src.models.onnx_conversion сравнивает PyTorch и ONNX Runtime на всех 6000 строках теста: максимальная разница вероятностей 1.2e-07, классы совпадают у всех строк, ROC-AUC одинаковый. При расхождении больше 1e-5 скрипт завершается с ошибкой, и стадия DVC падает.

## Оптимизация

| | размер, КБ | gzip, КБ | ROC-AUC | F1 | 1 строка, мс | 1024 строки, мс |
|---|---|---|---|---|---|---|
| ONNX fp32 | 71.9 | 54.6 | 0.7745 | 0.5250 | 0.038 | 0.423 |
| int8 (dynamic quantization) | 35.0 | 17.7 | 0.7731 | 0.5271 | 0.040 | 0.330 |
| pruning 50% + дообучение | 71.9 | 34.7 | 0.7744 | 0.5284 | 0.039 | 0.427 |

- Квантизация уменьшила модель в 2 раза (в 3 раза после сжатия) и ускорила батч 1024 на 22%, ROC-AUC снизился на 0.0014.
- Pruning обнулил половину весов без потери качества. Плотные ядра ONNX Runtime нули не пропускают, поэтому скорость не изменилась, а выигрыш виден только в сжатом размере.
- Для одиночного запроса разницы нет: время уходит на вызов сессии, а не на умножение матриц размером 40×128.

## Инференс: CPU и GPU

| | 1 строка, мс | 64 строки, мс | 1024 строки, мс |
|---|---|---|---|
| PyTorch CPU, 1 поток | 0.190 | 0.224 | 0.658 |
| ONNX fp32 CPU, 1 поток | 0.039 | 0.064 | 0.430 |
| ONNX int8 CPU, 1 поток | 0.039 | 0.058 | 0.324 |
| PyTorch CUDA (RTX 3080 Ti) | 0.490 | 0.506 | 0.552 |

- ONNX Runtime в 5 раз быстрее PyTorch на одиночном запросе.
- Дополнительные потоки CPU модели не нужны: с 8 потоками батч 1024 ускоряется до 0.33 мс, одиночный запрос не ускоряется.
- GPU медленнее CPU на всех размерах батча: время уходит на копирование данных на видеокарту и обратно.

## Нагрузочный тест API

Образ backend под Locust: 200 пользователей без пауз, 90% запросов /predict и 10% /predict/batch по 100 клиентов, 45 секунд. Лимит CPU контейнера соответствует поду на узле с таким числом vCPU, воркеров uvicorn столько же.

| CPU | запросов/с | p50, мс | p95, мс | p99, мс | ошибок |
|---|---|---|---|---|---|
| 1 | 754 | 260 | 310 | 340 | 0 |
| 2 | 1362 | 140 | 200 | 230 | 0 |
| 4 | 2213 | 88 | 130 | 160 | 0 |

Пропускная способность растёт почти линейно с числом CPU (×1.8 и ×2.9), значит, узкое место — Python-обработка запроса, а не модель.

## Конфигурация для продакшена

- Узлы CPU, GPU не нужен.
- Под API: 1 vCPU, 1 воркер uvicorn, 1 поток ONNX Runtime, память 512 МБ. Один под держит около 750 запросов/с на пределе, поэтому HPA масштабирует по CPU с целью 60%, то есть около 450 запросов/с на под.
- Модель: ONNX fp32 по умолчанию. int8 выгоднее только для пакетной обработки, он лежит в образе и включается переменной MODEL_PATH.
- Группа узлов app: STD3-4-8, на узле помещаются 3 пода API вместе с системными подами.
